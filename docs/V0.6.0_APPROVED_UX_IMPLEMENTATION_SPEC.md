## 2. UI 상세 행동 계약

### 2.1 D1 읽기 확대 (기존 장비 뷰 그대로)
- 장비 원형 UI의 라벨 위치/3개 SVG/7개 모니터/7개 설정을 보존. 기존 설정 타일 클릭=편집, 기존 `?`=설명 경로를 변경하지 않는다.
- **7개 모니터 읽기값:** `renderMonitor()`의 `.readout`에 독립적인 교육용 `읽기 확대` 접근 수단을 설치(키보드 버튼의 명확한 이름/대상 값 및 키보드 포커스 제공). 7열의 기존 수치를 오버레이하거나 화면에서 제거하지 않는다. 작은 폭에서 조작 버튼이 값·단위를 가리지 않아야 한다. 이를 충족하기 어렵다면 **장비 상단/학습영역의 공용 '표시값 크게 읽기' 진입 버튼+목록**으로 구현을 전환해도 되며 UX는 동일하게 7개 항목 모두 도달해야 한다(기술적 구현 판단).
- **7개 설정:** 현재 설정을 선택/설명하는 기존 버튼을 보존. `?` 진입 시 해당 설정의 큰 이름·값·단위·'교육용 설정값' 태그를 읽을 수 있는 표시 영역을 제공하되 기존 Help 내용/메뉴 접근을 잃지 않는다. 중복 아이콘을 320px 타일에 강제로 삽입하지 않는다.
- **Pressure/Flow/Volume:** 기존 SVG/inspector 사용성을 보존하고, 새 읽기 확대로 라벨·단위·'생성 곡선(실측 아님)' 및 관련 해설을 한 번에 확인한다.
- 별도 카드/대화상자로 구현할 경우 Tab 이동, `Escape` 닫기, 호출한 요소로 포커스 반환, zoom/resize 시 본문 접근, `aria-labelledby` 등 요구. 정보가 화면 밖에 잘리거나 뒤 요소로 키보드가 이동하면 FAIL.
- 읽기 확대는 **장비 설정을 변경하지 않는 순수 UI 상태**. 값은 고정 참조 또는 현재 committed 설정만 읽는다. 숫자를 환자 실측처럼 묶거나 새로 계산하지 않는다.
- 기존 7개 항목의 읽기 문제와 320/360px 가독성을 실기기 파일럿에서 별도로 평가한다. 테스트가 '잘림 없음'을 증명해도 실사용 가독성을 증명한 것은 아님.

### 2.2 D2 핵심 카드 정보 위계
- `CORE_LESSONS`의 6개 개념(Peep/Fio₂/VTE/f-fTOT/Ppeak/환자 우선 사정)을 삭제/개칭/교정 없이 재사용.
- 접힌 카드/한눈에 보기에는 **개념명+한 문장 의미+학생 관찰 포인트**가 드러나야 한다. 펼치면 기존 6개 상세 항목과 `CORE_LESSON_EXTRAS` 고급 용어, 원문 링크 모두 이용 가능.
- '요약/자세히/심화'만 표현을 구분; 초보 설명과 세부 임상 사실의 우선순위를 바꾸더라도 **현재 저장된 임상 문장의 의미는 변경하지 않는다**. 안전상 표현 변경이 불가피하면 별도 SME 검토 이슈 및 contentVersion 처리.
- 핵심 개념 6개/CORE 10문항/CASE 간 추천 경로를 간단히 안내. 이전 문항을 다시 제출하게 하거나 카드 열람을 '정답 완료'로 기록하지 않는다.

### 2.3 네 가지 자료 상시 구분
- `index.html`의 `.data-source-guide` (현재 닫힌 `details`)는 유지. 상세 설명을 펼치지 않아도 **4종 자료 한 줄 범례**가 학습 구역 시작부에 보이게 한다. 뷰포트 좁으면 두 줄/세로 재배치 가능.
- LAB 내 고정값에 대해서는 **'현재 장비에 미반영'**, 파형에는 **'교육용 생성 곡선'**, CASE에는 **'별도 가상 사례'**를 맥락상 분명히 표시. 색상만으로 의미를 전달하지 않는다.

### 2.4 D3 그래프 비교
- 기존 `generateWaveform(settings,start,duration,count)`를 재사용. 비교는 baseline/trial을 **같은 t0 = 0, duration = 16 s, count = 320**에 적용하는 결정적 스냅샷. 실제 기존 재생/일시정지 `waveformTime`에 연동하지 않아 기존 device 애니메이션에 영향 없음.
- Pressure/Flow/Volume 모두 같은 시간 그리드, 축 유형별 **baseline과 trial 전체의 공통 min/max**로 정규화. 압력·용적은 정상적인 0 baseline 스케일, Flow는 ± 최대 절대값의 영점 중앙선을 쓴다. **유형 간 축을 강제로 같게 하지 않는다**(단위가 다름). 축 라벨과 두 값을 함께 제공.
- 회색 점선 기준/강조 실선 실험. 기존 장비 위상별 색상 표시와 **별도의 LAB 그래프**여서 색 범례 혼선 없음. 텍스트 범례와 각 시리즈의 의미를 제공하고 선 종류로도 구별.
- 모바일은 동일 LAB 섹션에서 **Pressure/Flow/Volume 선택**으로 1개 대형 SVG를 표시하며 다른 2개 그래프 데이터는 유지. 데스크톱은 3개를 세로 순서로 보여주거나 그래프 선택을 공용으로 써도 되지만 기준/실험은 항상 같은 축에서 겹침.
- 그래프를 실제 VTE/SpO₂/Ppeak/fTOT 등 '환자 측정치'로 이름 붙이지 않는다. 기존 model 상수 35 mL/cmH₂O와 인위적 자발 이벤트는 **교육용 작화 가정**이며 임상 근거 없음.

### 2.5 D4 LAB 위치/진입·복귀
- `#panel-core` 내부에 `#core-labs` 같은 독립 섹션 신설. 장비 화면·CASE 주 탭, 서브 ALARM/CIRCUIT, Help 유지. 상단 학습 진도/관련 개념 카드/퀴즈 완료 페이지에서 LAB로 이동하는 **선택형 링크** 가능.
- LAB 개시와 종료, CORE 카드 복귀, CASE 01/02 이동 모두 명시적 버튼으로 한다. LAB을 종료/초기화하면 **LAB 실험 사본만** 삭제·초기화; 원래 장비/퀴즈/CASE·메모는 그대로.
- 자유 장비 탐색으로 이동해도 선택된 LAB 진행은 페이지 RAM에서 보존하거나 명시적 'LAB 다시 시작'으로 재개 가능. 화면 크기나 프레젠테이션 전환만으로 정답·입력·선택 그래프가 리셋되면 FAIL.
- LAB 조건을 완료하지 않고도 CORE 10문항·CASE 2개에 진입 가능.

### 2.6 D5 LAB 지식 확인
- 미션별 `predict`(예상 문제 1)과 `interpret`(결과 확인 1) **총 2문항 × 3미션 = 신규 6문항**을 별도 `lab-lessons.js`에 둔다. 기존 CORE 10/CASE 6과 합산·교체 금지.
- 상태 순서: `not-started → predict-unanswered → predict-answered → observation → interpret-unanswered → interpret-answered → review/completed`. 사용자가 기준/실험을 확인한 다음 결과 확인을 제출 가능하게 한다.
- 선택 전 정답/정답 해설/오개념 카드 노출 금지. 선택 뒤에 **3개 선택지의 근거/오개념과 앱의 한계**를 볼 수 있고, 완료된 단계의 과거 응답은 read-only(개별 답안 수정 불가)·실습 재시작 버튼으로만 풀기 초기화.
- LAB 성적은 인증점수가 아님. 기존 CORE/CASE score/정답/세션을 변경하지 않는다. '예상'의 옳고 그름을 임상 판단 능력으로 표현하지 않는다.
- 문항 콘텐츠는 `id`, `objectiveIds`, `phase`, `options`, `answer`, `explanation`, `sourceIds`, `evidenceKind`, `review{approved:false}`를 갖고 audit로 유일성/선택지/근거/정답 누락/사전 노출 위험을 검사. LAB 전용 `contentVersion`을 별도 부여하고 사후 전문가 검토는 여전히 pending.

## 3. 안내형 미션 3개: 고정한 예시 시작값과 교정된 모델 범위

**주의: 기존 DRAFT의 'LAB 시작 시 현재 장비 설정 사본을 기준으로 삼는다' 제안은 이 승인 구현 명세에서 교정한다.** 안내형 LAB에서는 학생이 현재 장비 값을 바꿨더라도 문제 정답이 안정적이어야 한다. 따라서 **`initialSettings()`의 공통 교육용 초기 설정을 복사한 뒤 미션별 입력으로 시연**한다. '기준/시험 모두 안내형 별도 사본; 현재 장비 설정과 무관'임을 화면에 항상 표기한다. 자유 비교 모드는 0.6에서 기본 범위 제외. 원래 committed state는 read-only도 할 필요 없이 독립 사용.

| ID / 학습목표 | baseline / trial (나머지는 초기 설정 그대로) | 예상 관찰(모델 안에서만) | 금지된 임상 오해 |
|---|---|---|---|
| LAB-01 PEEP | 5 → 8 cmH₂O | 생성 Pressure의 호기말 기준선과 흡기압 절대 위치가 상승; 교육용 용적/유량 곡선은 다른 설정이 같으면 변화하지 않을 수 있음 | SpO₂·산소화/실제 혈압/실측 VTE 변화 단정 금지 |
| LAB-02 f (설정 강제호흡수) | 15 → 18 /min | 결정적 모델에서 강제호흡 간격이 줄어든다. 인위적 자발 이벤트의 빈도/위치는 모델 가정 | 실제 fTOT/환자 노력 예측 금지 |
| LAB-03 FiO₂ | 40% → 60% | 이 버전의 `generateWaveform`은 FiO₂를 읽지 않으므로 **Pressure·Flow·Volume 모두 동일** | 실제 환자 산소화 반응이 없다는 뜻으로 해석 금지 |

- 예시 숫자 5/8, 15/18, 40/60은 **학습 선택값**이고 치료 권고/기기 권장 설정이 아니다.
- 성인 SIMV(PC)+PS 참고 화면 유지. 현재 실제 PB980 펌웨어/병원 로컬 구성 미검증.
- 신규 실습이 원래 모니터의 PEEP 5.8, fTOT 22, VTE 352, V̇E 7.43 등 독립 예시 숫자와 맞아떨어진다고 주장하지 않는다.

## 4. 설계 데이터/상태와 이벤트 계약

```text
Existing, unchanged:
 deviceCommittedState  -> original waveform / editor
 deviceEditState       -> Pending/Accept/Cancel
 monitorReference[7]   -> independent immutable display values
 coreQuizState         -> existing 10-question state
 caseSessions Map      -> CASE 01/02 per-case state
 reflectionNotes       -> separate in-RAM
 presentation/layout   -> view-only

New, strictly separate:
 readingUiState        -> inspected kind/key, focus origin, open/close only
 coreNavigationState   -> visible section / scrolling affordance only
 labSessionState (RAM) -> { labId, modelVersion, baseline, trial,
                            phase, predictedChoice, interpretedChoice,
                            selectedGraph, completed }
           ↓ pure waveformCompare(baseline, trial, window)
           ↓ two deterministic sample series, common scale per measure
           ↓ dedicated LAB SVG / explanation UI
```

**불변 조건 (테스트에서 강제):**
- 신규 `labSessionState.baseline`과 `trial`은 학습용 숫자 사본이다; 얕은 참조라도 기존 `state`를 직접 가리키지 않게 생성.
- LAB의 값 변경은 `state`, `editState`, `waveformTime`, `waveformPaused`, `inspectorActive`, `MONITOR_REFERENCE`, `coreQuizState`, `caseSessions`를 전혀 수정하지 않는다. 데이터 읽기까지 막지는 않으나 불필요한 결합 금지.
- LAB 측정을 위한 `generateWaveform` 호출에 쓰는 sampling parameters는 같고, 입력 범위/유효성 검사는 기존 설정 메타 `PARAMETERS` 및 waveform guards 활용.
- 같은 baseline/trial -> 동일한 수치 배열; FiO₂만 다른 값 -> 동일한 수치 배열; 극값/잘못된 입력 -> 기존 순수 model 유효성 검증 및 안전한 UI 오류 고지.
- 기존 설정 `?` Help는 여전히 Help, 원래 모달 Pending Accept가 유일한 commit 단계; LAB에는 실물 장비로 전달되는 Accept 버튼이나 실제 알람 시뮬레이션이 없음.
- LAB 세션은 페이지 RAM, 새로고침 초기화 명시. 브라우저 확대/보기/탭/장비 접기만으로 세션 손실 금지.
- 모든 구현은 소형 분리 모듈 권장: `src/waveform-compare.js` (pure), `src/lab-engine.js` (pure state transitions), `src/lab-lessons.js` (content). UI wiring 분리 규모는 안전한 점진 패치로 판단. 프레임워크/백엔드 미도입.
