## 1. 현행 기준선: 사실과 미완료 항목

### 이미 구현됨
- `index.html` PB980 **참고형 장비**: 7가지 설정과 Pending/Accept/Cancel/빠른 조작, 7개 **독립 고정** 모니터 표시, 3개 생성 파형/일시정지·분석·격자, 큰 글씨 읽기, 화면 배치/모바일 학습 우선.
- 핵심 개념 카드 **6개**, CORE 채점 문제 **10개**, 선택형 LAB **3개 × 비채점 문항 2개 = 6개**, 독립 CASE **4개 × 채점 문항 3개 = 12개**. CASE 03 MAS·CASE 04 RSV의 검사 예시 및 선택형 비채점 간호 행동 **2개**가 추가된 상태다. 채점은 CORE 10 + CASE 12 = 22개이고 LAB 6개는 합산 금지.
- `learn.html` 별도 Boyacto 스타일 **A 시작 → B 장비 탐색 → C PEEP 조작 연습 3종**. `src/learning-room.js`/`learning-room-state.js`의 상태는 `index.html`의 퀴즈·설정·CASE 상태와 **별도**다.
- 정적 웹앱이며 학습 세션은 **페이지 RAM**. 새로고침/서로 다른 문서 간 전환은 세션 보존을 보장하지 않는다. 배포 패키지는 명시적 정적 파일 화이트리스트로 구성된다.

### 남은 작업
- 학생 정답 없는 활동지, 교수자 LAB 운영·해설·오개념 자료, 전체 CORE/CASE/LAB 근거·ID·검토 상태 재감사.
- 처음 학습 → 개념 → 선택 LAB → 선택 CASE → 복습의 **권장 이동 경로와 명확한 복귀·진도 안내**. 강제 잠금/자동 채점·자동 완료 금지.
- 출처·생성/고정/가상 데이터 경계, 키보드/반응형/학생용 ZIP/교육 자료 분리, 실제 릴리스 버전 동기화.
- **전문가 감수·실제 학생 파일럿·실물 PB980 펌웨어 검증·실기기/스크린리더 전수검증은 미완료**. CI PASS로 대체 불가.

## 2. 한 버전의 제품 목표와 제외 범위

### 제품 목표
간호학생이 **(1) 앱/데이터 성격을 구분하고 → (2) 핵심 개념을 파악하고 → (3) PEEP/f/FiO₂ 파형 실험에서 예측·관찰·해석하며 → (4) 네 가상 CASE 중 하나에 적용하고 → (5) 자신의 오개념을 복습**하는 과정을 설명 없이 찾아갈 수 있게 한다. 활동지는 바로 인쇄/활용할 수 있으며 정답 해설은 교수자 참조 자료로 추적 가능해야 한다.

**권장 흐름이지 강제 커리큘럼이 아니다.** 언제든 CORE 퀴즈, LAB, 4개 CASE, 장비 탐색 및 기존 학습실로 자유 이동할 수 있어야 한다.

### 불변 및 절대 비목표
- 실측 환자 데이터, 생리학적 환자-폐 모델, SpO₂/ABGA/VTE/fTOT/혈압 예측, 실제 알람 작동, 정확한 PB980 펌웨어 시뮬레이션 추가 금지.
- 7개 설정·7개 고정 모니터 숫자·3개 생성 파형·기존 설정 편집, 보존된 CORE 10/CASE 12/LAB 6 정답·문항 ID·source IDs 임의 수정 금지.
- `index.html` 원형 PB980 화면과 `learn.html`의 A/B/C 학습실 **병합·대체 금지**(별도 사용자 승인 필요). 새 로그인, API, localStorage, IndexedDB, 서버 기반 진도 추적 금지.
- 교사용 정답을 학생용 정적 ZIP의 별도 문서로 포함 금지. 그러나 **저장소가 Public이고 클라이언트 정답은 JS에 있으므로 온라인 비공개 시험 보안이 존재한다고 주장하지 않음**.
- 병원·제조사 보증, 임상 승인, 간호사 독립 처방/조작 역량 인증 표현 금지. 현재는 사용자 승인 없는 GitHub Pages 활성화·사이트 배포도 제외.

## 3. 사용자 경험 설계

### 3.1 기존 `index.html` 화면 내 단일 추천 학습 경로 (필수)
현재 `#panel-core`, `#core-learning-content`, `#core-quiz-root`, `#core-labs`, `#panel-case` 및 `[data-learning-jump]`를 재사용한다.
- CORE 시작에 **짧은 4~5단계 학습 길잡이** 배치: "개념 읽기 → 10문항 확인 → 파형 LAB 선택 → CASE 선택 → 복습". 단계마다 행동 명확한 링크. 기존 빠른 이동 버튼과 역할 중복/시각적 소음 주의.
- 진도 표시가 필요하면 **이미 있는 각 엔진의 실제 상태**에서 읽기 전용으로 산출. 클릭·스크롤·단원 방문만으로 '완료' 변경 금지. 미진행은 '시작 전', 중간은 '학습 중', 실제 done은 '완료' 등으로 사실에 근거해 명시. LAB 각 3개와 CASE 각 4개를 독립 상태로 다룬다.
- LAB 완료 화면에는 **관련 핵심 개념 복습 / 다른 LAB 선택 / CASE 보기** 중 명시적 다음 행동을 제공. 문항의 정답이나 제출된 선택지를 다시 활성화하지 않는다.
- CORE 완료·CASE 완료 화면에서는 **다음 추천 단계와 돌아가기**를 제공. 새로고침은 상태 초기화됨을 고지.
- DOM 복제, 새 timer, 퀴즈/CASE/실험 세션을 한 Map으로 병합하는 방식 금지. 공통 navigation helper는 뷰 이동과 초점만 관리한다.

### 3.2 Boyacto `learn.html` 독립성 (필수)
- 초심자 오리엔테이션/PEEP 조작 연습용 **별도 진입점으로 유지**. 기존 `index.html` 세션과 상태 공유를 "구현됨"이라 표현하지 않는다.
- B/C 학습실 → `index.html` 복귀, 반대 방향 이동 시 **전체 페이지 이동/램 상태 초기화 가능성**을 사용자에게 명확히 알린다.
- 진행 중 학습 답안이 있을 때 확인 대화상자를 추가할지 여부는 **사용자 승인이 필요한 UX 선택**으로 별도 표기(아래 7절). 승인이 없다면 링크 구조/상태 정책을 바꾸지 않고 정보성 문구와 회귀 확인만 한다.

### 3.3 학생 활동지 — 기본 제안: 인쇄형 정적 HTML (승인 필요)
- 기본안 **`worksheet.html`**, A4 인쇄 스타일과 모바일 읽기 대응. `index.html` CORE에서 한 개의 "학생 활동지 열기/인쇄" 경로 제공. **빈칸형 자기기록지**, 정답·선택지별 정답 해설·학생 개인 성적을 넣지 않는다.
- 구성: 학습목표와 네 가지 데이터 구분 → PEEP/f/FiO₂ 실험 각 1개씩 예상/관찰/모델 한계 기록 칸 → CASE 01~04 중 하나를 선택한 판단 근거/모르는 점 기록 → 디브리핑 질문·임상 감수 전 주의.
- 브라우저 인쇄는 별도 새 탭에서 열되 기존 앱의 RAM state를 건드리지 않는다. 신규 파일은 `ci.yml` dist 화이트리스트, 링크 및 실제 패키지 열람 검증에 포함. 스크립트 의존성/가상 저장소 기능은 만들지 않는다.
- 대안: `docs/STUDENT_WORKSHEET_v0.6.0.md`만 제공하면 구현·테스트가 더 가볍지만 학생 앱과 연결성이 약하다. 사용자 최종 선택에 따른다.

### 3.4 교수자 자료 및 콘텐츠 감사 (필수)
- `docs/FACULTY_LAB_GUIDE_v0.6.0_DRAFT.md`: 3 LAB/6문항 ID, 학습목표, 정답 검토, 모든 선택지의 오개념, 디브리핑 질문, 출처 성격(앱 계산 근거/일반 임상 문헌), CASE 4개 연계 운영.
- `docs/CONTENT_REVIEW_MATRIX_v0.6.0.md`: CORE 6/10, LAB 3/6, CASE 4/12, 선택 행동 2, 알람·기기 참고 표기를 **이미 존재하는 source-of-truth ID에 연결**; `review.approved:false` 유지. 빈 칸은 "미검토" 명시.
- `docs/FACULTY_CLASS_GUIDE_v0.5.0_DRAFT.md`는 역사적 자료로 보존하거나 새 파일에서 대체 범위를 명시. 공개 GitHub의 교수자 파일은 누구나 볼 수 있다. 학생 ZIP에서 배제한다는 것은 **파일 묶음 분리이지 답안 접근권한 보호가 아니다**.
- 테스트가 가능한 고유 ID, 누락·중복, 기존 정답 및 문항 수, 출처 유형·내용 범위, ZIP 파일 목록을 검사. 실제 임상 내용 수정은 본 범위 밖.

## 6. 릴리스/실패 방지

- `v0.6.0 FINAL`은 **자동 검사, 정적 패키지, UI 흐름 및 명시한 기술 QA가 완료된 교육용 베타**라는 의미로만 사용. 임상 전문가 감수/교육 효과 연구 완료로 표현 금지. 필요한 수용 기준 미달이면 `v0.6.0 RC` 상태로 유지.
- 릴리스 표시 동기화: `src/sim-model.js VERSION`, `package.json version`, `index.html <title>`, `src/release-notes.js`, `README.md`, `PROJECT_SPEC.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, `DEVLOG.md`, `TEST_REPORT.md` 등.
- 클라이언트에 새 답안 보안/사용자 기록 저장/새 환자 모델/새 타이머/원형 기계 UI 대체/베젤 버튼 기능 가짜 구현 금지.
- 브라우저 실행 문제 발생 시 배포 로그·누락된 화이트리스트 모듈 확인; 두 차례 같은 수정 실패 시 원인 분석과 마지막 green main으로 안전하게 되돌리는 경로 제시.
- Pages 공개 배포/의학적 문구 수정/학습실 상태 통합은 별도 승인 없이는 하지 않는다.

## 7. 실제 코딩 전 사용자에게 확인받을 중요한 UX 선택 (미승인)

1. **학생 활동지 제공:** 추천 **A: 웹앱에서 열고 인쇄 가능한 정답 없는 HTML**(앱 흐름에 자연스럽지만 새 정적 파일·인쇄 QA 필요) vs **B: 저장소의 Markdown/PDF 자료**(구현이 단순하지만 앱 사용 흐름은 분리). 확정 전 A를 구현 완료로 간주하지 말 것.
2. **기존 앱 → 별도 학습실 이동 시 진행 상태:** 추천 **A: 진행 중인 CORE/CASE/LAB/Pending이 있을 때만 이동 확인**(실수 방지, 기존 navigation에 조건부 UX 추가) vs **B: 현재 링크 동작 유지 + RAM 초기화 안내**(단순하나 실수로 세션 유실 가능). 양쪽 모두 계정/저장/양방향 세션 동기화를 만들지 않는다.

위 두 가지 외에 기술적 구현 판단은 AI가 기존 코드·상태·위험을 확인해 자율 결정한다. **사용자가 결정하기 전에는 세션 동기화나 새로운 제품 흐름을 임의 승인받은 것으로 취급하지 않는다.**

## 8. 새 채팅 인수인계

새 채팅에서는 GitHub의 **최신 `main` 재확인** → 본 DRAFT와 상위 승인 명세 확인 → 위 두 중요한 UX 선택 확인 → B+ Definition of Ready → `v0.6.0` 통합 기능 브랜치 생성 → 내부 단계 A~D 구현·회귀 테스트 → PR FULL CI → 병합된 정확한 SHA의 FULL CI 및 산출물 검증 → 결과 보고 순으로 진행한다. **한 번에 거대한 코드 덤프/검증되지 않은 QA PASS/과거 스펙의 CASE 2종 가정 재활용을 금지한다**.
