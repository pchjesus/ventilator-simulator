## 1. 한 문장 비전
**'기초 용어 → 개념 → 형성평가 → 파형 변화 직접 비교 → 안내형 미니 실습 → CASE 적용 → 근거·오개념·디브리핑 복습'이 한 흐름으로 이어지는, 임상적 한계가 분명한 간호학생 교육용 시뮬레이터.**

핵심은 새 환자 생리모형이 아니라 **설정과 교육용 생성 파형의 관계를 학생이 실험·설명하고 환자 실제 사정과 분리하는 교육 경험**이다. 임상학적 인과효과 또는 PB980 동작 인증을 의미하지 않는다.

## 2. 기준 코드에서 직접 확인한 사실과 현재 위험
- `src/app.js` 약 1,350줄: 설정/팝업, mobile DOM 순서, CASE, CORE, 파형·회로·알람·학습 렌더링이 혼재. 기능 추가 전 영향 범위 통제가 중요하다.
- `styles.css` 약 775줄: 초기/후속 반응형, container query, 550/700/960/1100px 규칙 중첩. 새 UI의 우선순위 충돌 위험.
- `syncResponsiveSections()`은 동일한 장비·학습 DOM을 이동하고 좁은 화면에서는 장비를 숨긴다. 포커스가 숨겨지는 요소에 남는 문제/뷰포트 변경 중 조작창·학습 진행 손실을 **재현 시험으로 확인**해야 한다. 현재 결함으로 확정하지 않는다.
- `src/waveform-model.js`는 `peep/pi/ps/ti/rate`를 사용하는 **결정적 예시 곡선**; `fio2/trigger`는 현재 예시 파형을 바꾸지 않으며 SpO₂·ABGA·실제 VTE 모델이 없다.
- `src/case-engine.js` 및 `src/core-quiz.js`는 순수 상태전이, 페이지 RAM 위주. CASE 2개 × 3문항, CORE 10문항의 기존 정답·내용 버전은 앱 릴리스 버전과 분리.
- 7개 상단 모니터 읽기값은 **서로 독립적인 고정 표시 예시**이며 1명의 실제 환자 동시 자료가 아니다. CASE 가상 자료도 별도.
- 0.5.0 병합 `main` CI에서 Node 68개 통과 및 Chromium·정적 패키징 통과. 이는 실사용자 평가나 임상 승인과 다르다.
- INACSL의 사전설명·측정 가능한 목표·디브리핑, AARC 2024의 환자·인공호흡기 사정 원칙은 교육 방향을 뒷받침하지만 **개별 문항·시뮬레이터 계산·학생 독자 조작을 검증하지는 않는다.**

## 3. 기능 보호 계약 (MUST)
1. **기존 인터랙션 유지:** 설정 7개, 두 조작 모드, ± 길게 누르기/직접 입력/개별 기본값/전체 초기화, Pending/Accept/Cancel, 화면 프리셋 3개·보기 2개, Pressure/Flow/Volume 3개, grid/pause/inspect, 7개 독립 고정 모니터, CORE 카드 6개/10문항, CASE 01·02/개별 RAM 재개/디브리핑, CIRCUIT·ALARM·Help·교수자 미리보기.
2. **정답 불변:** CASE 01·02와 CORE 10문항 정답은 변경 금지. 의학적 정정 필요 시 별도 리뷰 이슈와 콘텐츠 버전 업데이트, 교수자 감수 후 처리.
3. **상태 분리:** 장비 설정·파형 vs 학습 실험 사본 vs CORE/CASE 답변·메모. 뷰 전환으로 답변 재제출·점수 변경·설정 변경이 일어나지 않도록 한다.
4. **의료 경계:** 실제 환자 생리학·ABGA·SpO₂·실측 VTE 계산, 진단·처치 권고, 실시간 기기 알람·회로 고장 시뮬레이션을 0.6 범위에서 제외. 오해를 유발하는 실측처럼 보이는 숫자/장비 알람 추가 금지.
5. **보안·배포:** Private 유지, 공개 Pages/외부 배포 없음. 정답 포함 교수자 문서는 정적 학생 웹 ZIP에서 분리; 인증 기능으로 표현 금지. 실제 환자·학생 식별정보 수집 금지.
6. **검증:** 구현 완료 ≠ CI 통과 ≠ 학생 사용성 평가 ≠ 임상 감수. 각 항목 별도 표기.

## 5. 0.6 핵심 기능의 사용자 관찰 경로

**학습자가 보는 화면 (권장안)**
1. 처음 진입: 안전 범위와 4가지 자료 구분, `개념 학습 시작` 또는 `장비 탐색`.
2. CORE: PEEP·FiO₂·VTE·f/fTOT·Ppeak·환자 우선 사정 카드와 문항 10개를 기존 방식대로 사용.
3. `파형 비교 실습`: 교육용 기준 설정 사본을 선택 → 실험값을 하나 바꾸기 → 같은 구간/같은 축의 **생성 파형** 비교 → 예상한 시각적 변화를 확인. 생성 용적을 '실측 환자 VTE'처럼 명명하지 않음.
4. 미니 실습: 예상 → 설정 한 가지 변화 → 곡선 읽기 → 변화 설명/오개념과 근거 → 초기화; 피드백은 학습 설명이며 치료·간호 중재 지시 아님.
5. 기존 CASE 01 또는 02 이동: 실제 관찰·지도자 보고를 강조. 실습 점수와 CASE 점수의 합산·임상 역량 인증 금지.
6. 종료: 무엇을 배웠는지, 어디를 복습할지 확인하고 디브리핑 메모(기존 RAM 방식)를 활용.

**3개 미니 실습 제안 (학생에게 보이는 관찰만 다룸)**
- LAB 01 PEEP: 교육용 압력 파형의 기준선 변화 관찰. 폐포·SpO₂·혈압이 실제로 변했다고 주장하지 않기.
- LAB 02 f: 같은 시간창의 강제호흡 간격 변화 관찰. 표시 fTOT/실제 환자 총 호흡수 예측 아님.
- LAB 03 FiO₂: FiO₂ 설정을 바꿔도 이 모델의 파형이 바뀌지 않음을 비교해, **모델이 계산하지 않는 것** 이해하기. 실제 산소화 변화가 없다는 주장이 아님.

자유롭게 기존 PB980 참고형 화면을 탐색하는 길은 유지한다. 새 실습은 별도 선택 경로로 진입하며 실제 환자 상태를 조정하는 UI처럼 표시하지 않는다.

## 6. 설계 권고: 별도 실험 state + 순수 비교 모델

```text
committedDeviceSettings (기존 앱 설정)
  ├─ existing waveform and setting-editor (변경 최소)
  ├─ seven independent fixed display samples (절대 연동 금지)
  ├─ CORE quiz / CASE RAM states (절대 연동 금지)
  └─ on LAB enter -> immutable baseline snapshot
                         |
               labState {baseline, trial, selectedParameter, step, observations}
                         |
             pure generateWaveform(baseline, t0, duration, sampleCount)
             pure generateWaveform(trial,    t0, duration, sampleCount)
                         |
             shared axis/time scaling + plain-language qualitative explanation
                         |
             discard/reset LAB -> original committed settings unchanged
```

- `labState`는 장비의 `state`, `editState`, `caseState`, `coreQuizState`와 별도. 진입 시 설정 사본을 복사한다. 장비의 실제 committed 값을 실험 종료 때 '되돌리는' 방식보다 기존 학습을 회귀시킬 위험이 낮다.
- 두 파형은 같은 시작 시간·총 시간·샘플 수와 **통일된 축**을 사용해 시각적 오해를 줄인다. 비연동 FiO₂/V-TRIG 시 동일 곡선을 산출하는지 부정 사례도 테스트.
- 계산 모델을 새 생리 모델로 교체하지 않는다. `src/waveform-model.js`의 현재 결정적 곡선을 재사용하고, 인터페이스·입력 가드·예외를 별도 소형 모듈로 둔다.
- 미션/설명은 `lab-lessons.js` 같은 데이터 파일로 분리. 렌더/UI만 `app.js` 또는 기능 단위 모듈에 연결. 앱 전체 상태 관리 프레임워크/서버를 새로 넣지 않는다.
- `src/app.js`·`styles.css` 정리는 **측정된 변경 빈도와 회귀 위험을 기준**으로 영향 구간만 점진적으로 모듈화한다. 전면 리팩터링/디자인 대교체 금지.
- 학생 답변/디브리핑은 기존 원칙대로 RAM 전용. 브라우저 영구 저장/localStorage는 0.6 기본 범위 제외. 내보내기/저장 옵션은 개인정보·수업 UX 결정 후 별도 버전으로 논의.

**브라우저 검증 매트릭스:** 1440 / 1280 / 1100 / 960 / 700 / 360 / 320 CSS px, 학습/장비 보기, 3 레이아웃, 두 설정 조작 방식. 200% 확대와 320 CSS px 상당 reflow, 작은 터치 목표/간격, 색 대비, 키보드 Tab/Enter/Escape, reduced motion, 중간 viewport 전환, 원본 CASE 답안·퀴즈·설정 정합성, 정적 ZIP 실행. 주요 탭·설정·CASE 복합 조합은 **전수조합 대신 대표 pairwise + 위험 기반 테스트**로 제어.

**릴리스 게이트:** 단위/브라우저/빌드 PASS + 스크린샷 수동 비교/QA 기록 + Private PR 코드 리뷰 → `main` 병합 → 최종 `main` SHA CI 재검증. 자동 테스트 성공만으로 전문가 감수·실학생 효과 검증을 완료 표시하지 않는다.

## 8. 출시/사용성 검증 정의
- **코드 완료:** 0.6 통합 흐름·상태·학습 실습 기능 구현.
- **자동 검증 완료:** Node/Chromium/패키지 CI PASS, 회귀 수치와 스크린샷 기록.
- **교육용 베타 FINAL:** 코드+기술 QA와 문서/안전 경계를 충족한 경우. 실제 학습 효과 검증을 뜻하지 않는다.
- **학생 사용성 평가:** `docs/V0.5.0_USABILITY_PILOT_PROTOCOL.md`을 확대해 U1~U7 및 새 파형 실험 과제, 도움 요청/오해/진입 성공 비율 등을 기록. 실제 모집·실시 여부를 별도로 남김.

## 9. 최종 결정이 필요한 중요 UX 선택 (아직 미승인)
1. **실험의 상태 방식:** A **분리된 LAB 사본(추천)** — 기존 장비와 CASE를 전혀 변경하지 않음, 다만 실험/장비를 오갈 때 수치가 다른 이유를 안내해야 함. B 기존 장비 값을 직접 바꾸고 복원 — 손쉬운 직관성, 그러나 Undo/진행 중 편집/학습 상태 회귀 위험이 큼.
2. **미니 실습 노출:** A **선택형 3개(추천)** — 기존 학습 경로와 자유 장비 탐색을 보존. B 모든 학생에게 필수 — 일관된 수업 진행이 좋지만 콘텐츠 길이와 이탈 부담 증가.
3. **0.6의 CASE 확대:** A **기존 2개 유지·LAB 연결(추천)** — 교육 목적과 근거 검토 부담 통제. B 새 CASE 03 추가 — 적용 사례 다양화 가능하지만 시나리오·정답·임상 전문가 감수까지 별도 필요.
4. **답변 보존 범위:** A **페이지 RAM 유지(추천)** — 수집·보안·마이그레이션 위험 최소. B 브라우저 새로고침 후 복원 — 편의성 향상, 민감정보 오해/기기 공유/저장 범위·삭제 고지와 스키마 관리 필요.

위 A안은 개발 제안에만 반영한다. 실제 사용 경험을 크게 변경하는 중요한 선택은 구현 전에 사용자 확정이 필요하다. UX 선택 전에도 회귀 탐지·접근성 개선·문서 정리 등 위험 낮은 준비는 가능.
