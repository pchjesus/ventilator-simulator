## 3. 교육 내용 적합성 제안

### 초보 간호학생의 학습 목표
- **확인**: PB980 참고 화면의 '설정값/고정 예시 모니터/교육용 파형/별도 CASE 가상 수치'를 구분.
- **이해**: FiO₂, PEEP, f/fTOT, VTE, Ppeak, 환자 사정의 기초 정의와 단위.
- **적용**: 관찰할 환자 상태·지표 추세·추가로 확인할 정보를 말하고, 독자적 설정 변경 대신 지도자에게 보고할 필요를 인식.
- **성찰**: 선택 이유와 틀린 부분을 설명하고, 부족한 정보와 학습 한계를 식별.
- **비목표**: 실물 PB980 독자 조작 숙련, 환자 상태 추론/치료 결정, ABGA 계산 모델, 자동 알람 판단, 임상역량 인증.

### 설명 카드의 추천 형식
1. 쉬운 정의: "이 숫자/용어가 뜻하는 것" (1~2문장).
2. 왜 중요한가: 인과 관계를 보수적으로 설명, 절대적인 생리 반응을 단정하지 않음.
3. 어디서 보나: 설정 카드 vs 고정 환자 데이터 영역을 따로 표시.
4. 간호학생에게 중요한 관찰: 실제 환자 사정/보고의 역할; 기관 지침 우선.
5. 미니 예시: 설정 수치가 무엇을 의미하고, 무엇을 알 수 없는지.
6. 대표 오개념 1개와 '왜 아닌가'.
7. "더 알아보기": Pplat, PBW, auto-PEEP 등 심화 용어와 원문 참고.

\`core-quiz.js\`의 모든 정답·근거 해석·교수자 검토 상태를 안전하게 유지한 채 표현/보충 설명의 유익성을 탐색. 의학적 주장이나 새로운 정답을 추가할 때는 해당 항목 전문 검토를 요구.

### CASE 추천 진행
진입 전 목표/가상 자료 구분 → **상황 읽기** → **무엇이 문제인가(관찰할 신호)** → **추가 정보 및 학생 역할** → **지도자 보고** → **왜 그런가 복습/디브리핑**.
- CASE 01/02의 기존 3문항 순서·정답을 먼저 유지. 과거 응답은 read-only 미리보기, 완료 후 전체 근거·복습.
- 현재 항목/과거 완료/다음 단계 분리. 펼칠 수 있는 상황 자료는 매 단계 제공하지만 중복 목표 목록 제거.
- 정답 선택 외 '이유는 무엇인지' 예시/문장틀을 추가하는 경우 점수화하지 않는다. 과도한 입력 필수화는 피한다.
- 사례 설계는 INACSL prebriefing, measurable objectives, guided facilitation, planned debriefing 원칙을 참고한다. 문헌 준수/인증을 선언하는 것은 아님.

## 6. 회귀/검증과 학습평가를 분리

| 검증 축 | 예시 테스트 | 주체 |
|---|---|---|
| 코드 무결성 | 7설정 유지, pending/Accept/Cancel, 개별 초기화, 퀵 홀드, 모니터 고정, 곡선·pause/inspect | 개발 자동 테스트 |
| 레이아웃 | 3 presets × 2 presentations × 2 control modes, 모니터 긴 숫자 완전 표시, overflow 없음 | 실제 Chromium 캡처+DOM bbox |
| 모바일/접근성 | 320/360/700, 키보드 포커스·화면 순서·44px 권장 터치영역, WCAG 2.2 텍스트 대비(일반 텍스트 4.5:1) | 자동+사람의 검사 |
| 학생 학습 | 용어를 자력 설명할 수 있는가, 설정/측정/가상 자료를 구분하는가, 도움 없이 CASE 시작/복습 가능한가 | 실제 학생 파일럿 필요 |
| 교수자 학습 | 목표 제시·중간 복습/디브리핑 운영에 불편 없는가 | 실제 교수자 피드백 필요 |
| 임상 정확성 | 기기 사양, 간호사의 역할, 위험 징후 보고 원칙, 사례/정답/근거 | 외부 전문 감수 필요 |
| 안전/프라이버시 | 실제 환자 치료 사용 금지, CASE/모니터 계산 분리, Private GitHub, no persistent learning record | 개발·검수 |

분기별 패치마다: 구조 파악 → 영향표 → 최소 수정 → 단위/브라우저 회귀 → 스크린샷 육안 검토 → PR 리뷰 → 병합/최종 SHA CI. 자동화의 성공과 임상적 승인/학습효과의 입증은 구분.

### 교육 및 접근성 외부 자료 (방향 제안의 참고)
- INACSL. *Healthcare Simulation Standards of Best Practice*: https://www.inacsl.org/healthcare-simulation-standards
  - Prebriefing, Simulation Design, Outcomes and Objectives, Facilitation, Debriefing 내용은 설계 방향의 기준. 앱이 INACSL 인증을 받았다는 의미는 아님.
- Goodfellow et al. (2024). *AARC Clinical Practice Guideline: Patient-Ventilator Assessment*. https://pmc.ncbi.nlm.nih.gov/articles/PMC11298231/
  - 직접 환자 사정, VT, PEEP/auto-PEEP 및 FiO₂ 평가 원칙. 개별 임상 사례의 정답이나 학생의 조작 범위를 직접 승인하지 않음.
- W3C. *WCAG 2.2 Understanding SC 1.4.3 Contrast (Minimum)*. https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
- W3C. *WCAG 2.2 Understanding SC 2.5.8 Target Size (Minimum)*. https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum
  - 4.5:1 일반 텍스트 대비, target size 기본 24 CSS px(조건/예외 포함). 44 CSS px는 편의성 중심 프로젝트 권고로, 해당 성공기준의 엄밀한 최솟값이 아님.
