### P0-1. 장비 원형의 7~10px 초소형 라벨 [F/H]
- 근거: styles.css의 .inactive-alarm 7px, .reference-flag 7~9px, .graph-head 8~11px, 모바일 bezel 보조라벨 5~8px, 일부 .readout .label 9~11px 등. 원래 7개 모니터의 긴 값 잘림은 v0.4.7에서 수정되었음(현재 알려진 버그로 재기재 금지). CORE 본문 기본 학습 14px 규칙이 있지만 장비 외형·메타는 여전히 작음.
- 사용자 문제: 좁은 PB980형 패널에 수치/단위/라벨을 함께 표시하면서 학생이 확대/도움말을 오가지 않고 바로 해석하기 어려울 가능성이 높음. **실제 학생 가독성 불량은 아직 관찰로 확정하지 않음.**
- 권장 해결: 원래 PB980 모사 화면은 보존하되, 각 고정 모니터/설정/파형을 선택하면 **교육용 읽기 확대 카드**로 큰 한국어 이름·원문 약어·단위·자료 종류·핵심 설명 제공. 장비 장식 작은 글자에는 필수 학습정보를 의존하지 않는다. 본문/선택지 기본 학습 보기에서 14px 이상을 권장 목표로 두고, 일반 본문 16px까지의 증대는 실제 스크린샷/모바일 회귀 결과로 결정.
- 대안: (B) 모바일 장비판 자체를 다행 구성으로 리플로우(고증 약화·레이아웃 회귀 큼), (C) 전체 화면 확대/양방향 팬(조작 탐색/가로 스크롤 및 포커스 문제). 권장 A.
- 검증: 320/360/700/960/1100/1280/1440 및 200%/400% 확대, 읽기 확대 패널 접근/닫기·Tab/Escape/포커스 복귀, 7개 읽기값/각 단위와 파형 기능 유지. 모의 장비의 그래프는 2차원 스크롤 예외 해석을 근거로 검토하되 일반 학습 텍스트에는 적용하지 않음.

### P0-2. 네 자료 출처가 접힌 설명 안에만 상세 표시 [F/H]
- 근거: index.html .data-source-guide는 open 속성 없는 details. warning 한 줄과 onboarding은 있지만, '7개 서로 독립적인 고정 표시값' 등 상세한 4종 구분은 펼쳐야 읽음. 모니터 7개는 수치가 일관된 한 환자 자료가 아님.
- 위험: f 변경→가상 파형 변화→상단 고정 fTOT 22 등의 독립성을 놓치면 거짓 생리학을 학습할 가능성. 기존 고정값과 CASE는 절대 동기화하지 않음.
- 권장 해결: 기본 학습 상단에 **한 줄 요약 레전드: 설정 | 독립 고정 예시 | 계산된 교육용 파형 | 별도 CASE 가상자료**를 상시 노출. 전체 해설은 현 details 유지. 읽기 확대 카드와 LAB에는 관련 출처 배지를 맥락에 맞게 표기. 숫자 값을 임의로 변경하거나 한 환자처럼 재구성하지 않음.
- 검증: 네 가지 범주를 학생이 설명할 수 있는지 과제(U1)와 참/거짓 이해 확인, 화면 리그레션, 회색 배지가 아니라 텍스트로 의미 전달.

### P1-1. 개념 6장 × 6개 설명 항목 + 심화 × 10문항을 한 학습 흐름에서 제시 [F/H]
- 근거: src/app.js renderCoreLearning은 각 CORE_LESSON에 6개의 설명(정의/원리/관찰/오개념/예시/앱 구분), 심화와 출처를 넣고, 바로 같은 CORE에 10문항을 렌더한다. v0.5.0 개념 구조는 의학/앱 한계를 충실히 구분함.
- 위험: 충분히 중요한 정보를 모두 담았지만 입문자가 어디에 집중해야 할지 판단하기 어려울 수 있음(인지부하 가설, 학생 파일럿 필요). 10문항 모두를 CASE 진입의 필수 통과 조건으로 만들면 기존 자유 탐색 훼손.
- 권장 해결: 카드 제목/1문장/핵심 구분/관찰 질문을 먼저 보이는 '한눈에' 단계, 펼치면 기존 여섯 상세 항목. '빠른 학습 순서' 추천만 제공; 문항/CASE 자유 진입 유지. 학생이 임상 관찰·보고와 **설정 조작의 차이**를 매 카드에서 학습.
- 검증: 접힘/펼침/개념 복습/문항 복귀 시 답변 불변, 학생 U2/U4, 보조 설명 누락 없음.

### P1-2. 학습 진행 힌트가 실제 답변/방문 여부와 구별되지 않음 [F/H]

- 검증: 퀴즈 시작 전/중/후, CASE1/2 개별 완료, 탭 복귀, 장비 reset, 새로고침(페이지 RAM 초기화 안내).

### P1-3. 새 LAB 비교 UI와 기존 압력·유량·용적 색범례 충돌 [F/H]
- 근거: src/waveform-model.js generateWaveform()은 pressure,flow,volume 3개와 mandatory/spontaneous/expiration phase를 생성. PEEP/Pi/PS/Ti/rate만 샘플에 영향을 주며 FiO₂/V-TRIG는 영향을 주지 않음. 설정된 Pi/PS는 단순 35mL/cmH2O 데모 상수 등으로 예시 용적 생성. 측정량이 아님.
- 권장 해결: 그래프 위에 '기준(점선 회색)'과 '시험(실선 강조)'을 하나의 축/시간창에 겹치되 원래 위상 색상은 설명 레이어로 분리하거나 통일성 점검. 시간 0초 기준, 동일 샘플 수, 공통 축 min/max; 부호(Flow +/−) 확인. 모바일에는 3개 그래프 중 한 번에 하나의 종류를 선택해 크게 읽고, 압력/유량/용적을 전환 가능하게 한다. 패널에는 변경된 한 설정과 예상/관찰 차이만 명시.
- 대안 B: 좌우 나란히 기준/실험 2열(데스크톱 비교 쉬우나 모바일 좁음), C: 이전/이후 스위치(모바일 간결하나 차이 비교 어려움). 권장 A의 단색선/점선 대비 + 모바일 1그래프.
- **수치의 교육적 한계:** 예시 Volume은 호기 측정 VTE 아님, 7고정 모니터와 산술·생리학 정합성 주장 금지. FiO₂ 40→60% 변경 시 파형이 동일하다는 것은 '현재 앱 모델의 비연동'만 뜻함.
- 검증: 동일 baseline/trial -> identical arrays, FiO₂/V-TRIG only -> identical, PEEP 변동 -> 예시 압력 기준선 변화, f 15→18/min -> 강제호흡 주기 변화; 양쪽 축·t0 같음, trial reset 원본 committed 불변. v0.3.7 inspect/pause/3파형 정상.

## C. v0.6.0 실제 학습 시나리오 및 화면 구조 (권장)
화면 최상단: 현 경고/보기 2종 유지 → 4자료 한 줄 구분 → '추천 순서' 시작 버튼. 기본 탭 핵심 개념/CASE/?설명 3개 유지(4번째 메인 탭 신설 금지: 모바일 폭·인지부하 위험).
CORE 카드: [짧은 정의 + 관찰 포인트] → [현재 기존 전체 설명 펼침] → [형성평가 10문항] → [선택형 LAB 시작]. CORE 퀴즈로 바로 이동·CASE 자유 시작 허용.
LAB 전용 하위 화면: '교육용 예시 · 실제 환자 수치 아님' → ①목표 ②변화 예상(정답은 확인 뒤 노출) ③기준·실험 입력 A/B ④동일 축 파형 ⑤관찰 3지선다(새 LAB 문항) ⑥왜 그런가 + 기기 한계 ⑦다시 해보기 / 관련 CASE / CORE 복귀.
LAB 조건: 실험 사본은 원래 committed settings/editState에 영향 없음, 네 가지 정보 출처/기존 CASE 답안도 변하지 않음. LAB 입력은 원래 허용 교육 범위를 준수; 원본 상태와 실험 상태가 다르면 상시 '원본 장비에는 미반영' 표시.
LAB-PEEP: baseline 5 → trial 8 cmH2O; 생성 압력 베이스라인 상승을 관찰. 실제 SpO₂/혈압·VTE 산출 금지.
LAB-f: baseline 15 → trial 18 /min; 일정시간창에서 강제호흡 간격 비교. '예시 자발 이벤트'는 실제 자발호흡/trigger가 아니라는 문장 유지.
LAB-FiO₂: baseline 40 → trial 60%; 동일 생성 파형 확인. 실제 혈액 산소화 영향이 없다는 뜻이 아니라 모델의 제한임.
일반 탐색에서는 Pi/PS/Ti/trigger 원래처럼 조작 가능. LAB 3개 외 자유 비교는 v0.6 선택 옵션으로만 열고 임상 검증되지 않은 비교 문장을 자동 생성하지 않음.

| D4 LAB 접근 | 기존 CORE 안에 '실험 시작' 및 복귀, LAB 3개 선택형 | 독립 메인 탭(탐색 쉽지만 좁은 화면 탭 과밀) | 세 실험 반드시 완료해야 CASE 진입(교육 진입장벽) |
| D5 LAB 문제 | 각 1개 예상+1개 결과 확인, 설명·오개념은 제출 후(추천) | 정답 없이 그래프 자유 탐색(실습 평가 어려움) | 5개 이상 미션/점수 합산(과도한 부담) |
| D6 CASE 연결 | LAB 종료에서 CASE 01/02 추천만(선택형) | LAB 완료 즉시 CASE로 강제 이동 | CASE 03 신규 제작·전문가 검토(0.6 범위 확대) |
| D7 기록 보존 | 기존 페이지 RAM 상태 유지 | 새로고침용 localStorage(편리하지만 삭제·고지·버전 관리 필요) | 내보내기 파일(과제화/개인정보 보호 설계 필요) |

중요: A안은 **제안**이지 사용자 승인 아님. 과거 확정된 0.5.0 요구(고정 7 모니터, 2 CASE/기존 정답, 장비 원형 유지, 교사 별도 배포 등)를 뒤집지 않음. D1-B처럼 과거 요구와 충돌할 수 있는 선택은 추가 확인과 범위 정의가 선행되어야 함.

## F. 출시 전 수용 기준 (예시: 검증 성공 전 PASS 표시 금지)
1. 기본 학습 핵심 설명/선택지는 작은 본문을 읽도록 강요하지 않고; 기능성 콘텐츠에 글자크기·행간·콘트라스트 점검표와 육안 검토 기록을 남긴다. 일반 학습문에 최저 14px 설계 목표, 신규 주 설명 16px 권장(대상 기기/기본 UI에서 실제 확인 후 확정).
2. 네 정보 범주가 설명을 펼치지 않아도 보인다. 학생에게 '상단 VTE352와 선택한 Pi는 계산으로 연결되는가?' 같은 이해 점검. 실제 학생 수행 증거 없는 상태에서는 '검증 준비'만 표기.
3. LAB 입력·그래프 비교 후 원래 교육용 7설정/고정 7모니터/기존 파형·CORE 10문항/CASE 2개 답안, 진행상태, 메모의 동등성 검사. 정답 사전 노출 없음.
4. PEEP(5→8) / f(15→18) / FiO₂(40→60) 미션의 기대 시각 변화/비변화를 **동일 시뮬레이터 생성 모델**로 단위 테스트하고 코드 정합성 스냅샷 기록.
5. 7 breakpoint 1440/1280/1100/960/700/360/320, keyboard focus + Escape + resize-with-dialog, reduced motion, zoom 200/400, touch target 및 2종 보기/3종 레이아웃의 주요 상호작용을 회귀 검사. 시각 스크린샷 검수·물리 스마트폰/스크린리더 검토는 별도 단계.
6. 기존 교수자 공개 미리보기 인증 부재 고지 및 교수자 답안 파일의 학생 ZIP 배제 확인. clinical reviewer approval는 실제 서명 전 pending 유지.
7. Private PR -> patch-by-patch CI -> main merge -> actual main SHA/CI verify. v0.5.0 baseline으로 롤백 가능한 Git SHA 기록.
